# Contributing

External participation is welcome through the public
[DOTSOFT-SA/darius-demonstrator](https://github.com/DOTSOFT-SA/darius-demonstrator)
repository. No contribution is accepted automatically.

## Propose work

- Search existing issues before opening one.
- Use the bug template for reproducible defects and the feature template for scoped proposals.
- Keep changes focused on the controlled demonstrator.
- Discuss dependency additions, schema changes, new datasets, and new model artifacts before implementation.

## Development setup

Create a virtual environment and install `requirements.txt`. Install the Flower requirements only when changing the network path. Run `npm ci --prefix browser-edge-client` for browser changes.

Before submitting a pull request, run:

```bash
python scripts/reproduce.py --rounds 3
python -m unittest discover -s tests -v
npm test --prefix browser-edge-client
npm run build --prefix browser-edge-client
```

Update documentation and generated hashes when behavior changes. Explain any command you could not run.

## Data and model gate

Do not contribute real, sampled, perturbed, anonymised, or pseudonymised municipal records. New synthetic data must be independently generated by documented rules and fixed seeds. New models must record synthetic-only provenance and be reproducible from included generators. Reviewers will reject ambiguous data or binary provenance.

## Pull-request review

Maintainers review correctness, scope, tests, privacy, security, provenance,
licensing, and documentation before acceptance. Approval and merging are
discretionary; opening a pull request does not transfer ownership or guarantee
inclusion. Unless separately agreed in writing, contributions are submitted
under the repository's MIT License and contributors retain copyright in their
contributions.

## Conduct

Be respectful, specific, and constructive. Harassment, discrimination, threats, doxxing, and publication of private or security-sensitive information are unacceptable. Maintainers may edit or remove content and restrict participation to protect contributors and the project. A fuller code of conduct can be adopted later if community scale warrants it.

Report vulnerabilities privately using `SECURITY.md`, not through a public issue.
