# Security policy

This is non-production demonstrator software. Supported versions, if any, are
identified in published GitHub releases; no support-time or response-time SLA
is promised.

Report suspected vulnerabilities through the repository's **Security and
quality → Advisories → Report a vulnerability** private channel. Do not include
secrets, exploit details, or personal data in public issues.

**Tagged-release gate:** the repository administrators must enable private
vulnerability reporting and assign a monitored DOTSOFT security maintainer
before publishing the first tagged release.

Reports should include the affected revision, reproduction steps, impact, and any suggested mitigation. Maintainers will acknowledge and triage reports before deciding disclosure timing; no response-time SLA is claimed.
